# Weekly Tech Journal API

Base URL (production): `https://weekly-tech-journal.vercel.app`

All endpoints live under `/api/entries`. Requests and responses are JSON.

## Authentication

| Method | Needs token? |
|---|---|
| GET | No (public) |
| POST, PATCH, DELETE | Yes |

Send the token in a header:

```
Authorization: Bearer <API_WRITE_TOKEN>
```

Get the token privately from the backend owner. Never commit it, never put it in a `NEXT_PUBLIC_` variable, and never call write endpoints from browser code. Call them from a server action or a Next.js route handler so the token stays on the server.

Local setup: add this to your own `.env.local`:

```
API_WRITE_TOKEN=your-token-here
```

## Response format

Success:

```json
{ "data": { } }
```

Lists also include paging info:

```json
{ "data": [ ], "meta": { "limit": 20, "offset": 0 } }
```

Error:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Invalid input", "details": { } } }
```

| Code | HTTP status | Meaning |
|---|---|---|
| VALIDATION_ERROR | 400 | Bad body, bad JSON, bad id, or bad query params |
| UNAUTHORIZED | 401 | Missing or wrong token on a write endpoint |
| NOT_FOUND | 404 | No entry with that id |
| INTERNAL_ERROR | 500 | Server problem |

`details` is only present on validation errors.

## Entry object

```json
{
  "id": "93411311-ff14-4c7e-bd9f-fbbca98fab1e",
  "title": "Live test",
  "content": "# Hello",
  "createdAt": "2026-10-16T15:17:21.204Z",
  "updatedAt": "2026-10-16T15:17:21.204Z"
}
```

| Field | Type | Rules |
|---|---|---|
| id | string (UUID) | Generated by the server |
| title | string | 1 to 200 characters, trimmed |
| content | string (markdown) | 1 to 50000 characters |
| createdAt | string (ISO 8601) | Set on create |
| updatedAt | string (ISO 8601) | Changes on every update |

## GET /api/entries

List entries, newest first. Public.

Query params (optional):

| Param | Default | Rules |
|---|---|---|
| limit | 20 | Integer, 1 to 100 |
| offset | 0 | Integer, 0 or more |

```bash
curl "https://weekly-tech-journal.vercel.app/api/entries?limit=10&offset=0"
```

Response `200`:

```json
{
  "data": [ { "id": "...", "title": "...", "content": "...", "createdAt": "...", "updatedAt": "..." } ],
  "meta": { "limit": 10, "offset": 0 }
}
```

## GET /api/entries/:id

Get one entry. Public.

```bash
curl https://weekly-tech-journal.vercel.app/api/entries/93411311-ff14-4c7e-bd9f-fbbca98fab1e
```

Responses: `200` with the entry, `400` if the id is not a UUID, `404` if not found.

## POST /api/entries

Create an entry. Token required.

Body (both fields required):

```json
{ "title": "My week", "content": "# Notes\n- learned Drizzle" }
```

```bash
curl -X POST https://weekly-tech-journal.vercel.app/api/entries \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $API_WRITE_TOKEN" \
  -d '{"title":"My week","content":"# Notes"}'
```

Responses: `201` with the new entry, `400` for invalid input, `401` for a missing or wrong token.

## PATCH /api/entries/:id

Update an entry. Token required. Send at least one of `title` or `content`.

```bash
curl -X PATCH https://weekly-tech-journal.vercel.app/api/entries/ENTRY_ID \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $API_WRITE_TOKEN" \
  -d '{"title":"New title"}'
```

Responses: `200` with the updated entry, `400` for invalid id or empty or invalid body, `401`, `404`.

## DELETE /api/entries/:id

Delete an entry. Token required.

```bash
curl -X DELETE https://weekly-tech-journal.vercel.app/api/entries/ENTRY_ID \
  -H "Authorization: Bearer $API_WRITE_TOKEN"
```

Responses: `200` with `{ "data": { "id": "..." } }`, `400`, `401`, `404`.

## Using it from Next.js (server side only)

Reading (works anywhere, no token):

```ts
const res = await fetch(`${process.env.API_BASE_URL}/api/entries`, { cache: "no-store" });
const { data } = await res.json();
```

Writing (server action or route handler only):

```ts
"use server";

export async function createEntry(title: string, content: string) {
  const res = await fetch(`${process.env.API_BASE_URL}/api/entries`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${process.env.API_WRITE_TOKEN}`,
    },
    body: JSON.stringify({ title, content }),
  });
  const json = await res.json();
  if (!res.ok) throw new Error(json.error?.message ?? "Request failed");
  return json.data;
}
```

Set `API_BASE_URL=https://weekly-tech-journal.vercel.app` in `.env.local` (no `NEXT_PUBLIC_` prefix needed for server code).

## Rendering content

`content` is markdown. Render it with `react-markdown` and `remark-gfm`. Edit it with `@uiw/react-md-editor`.
